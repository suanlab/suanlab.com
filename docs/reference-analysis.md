# IDC 온톨로지 참고 사이트 분석

확인일: 2026-10-05. 근거는 제공된 `idc-audit-ontology-source.zip`과
[공개 홈페이지](https://ontology.kongjae.com/), [발표 페이지](https://ontology.kongjae.com/present)다.
로그인하거나 실제 보안 조치·AI 호출을 실행하지 않았다.

## 실제 화면 구성

홈페이지는 로그인 없이 열리는 제품 소개 페이지다. 핵심 문제를 먼저 설명하고
관측 → 조사 → 등록 → 판정 → 조치 → 재점검 → 근거의 7단계 흐름을 보여 준다.
규칙 엔진, AI 에이전트, 호스트 에이전트, 사람의 역할을 분리해 설명한다.
스크롤에 따른 설명과 그래픽, 로그인 및 발표 페이지로 이어지는 동선이 핵심이다.
동작을 멈추는 버튼도 있다.

발표 페이지는 별도의 전체 화면형 React 인터페이스다. 확인 시 본편은 13장이며
도입·문제·온톨로지·설계·시연·검증·정리의 장 구분과 부록, 이전/다음 버튼이 보였다.
두 URL 모두 브라우저에서 HTTP 200을 반환했다.

## 소스에서 확인한 기술 구성

| 영역 | 소스 근거 | 구현 |
| --- | --- | --- |
| 웹 앱 | `package.json` | Next.js 16.3.5, React 19.2.3, TypeScript, React 컴포넌트 |
| 서버·데이터 | 패키지 및 README | PostgreSQL/Drizzle, tRPC, Better Auth; RDF/SPARQL, Oxigraph, SHACL |
| 그래픽 | `package.json`, 발표 컴포넌트 | Three.js, React Three Fiber/Drei, 그래프 시각화 라이브러리 |
| 발표 탐색 | `src/components/present/nav.ts` | 장 번호와 장 내부 단계 분리, 키보드·숫자 이동·해시·스와이프 로직 |
| 실시간 발표 | `src/components/present/live.ts`, `src/app/api/present/live/` | 서버 채널을 통한 발표 위치 동기화; SuanLab의 정적 호스팅과 다른 구조 |
| 호스트 수집·실행 | `hostagent/`, README | 별도 Go 에이전트; 서명 확인 뒤 승인된 작업 실행 |
| 배포 | `deploy/README.md` | OCI ARM64 호스트, GitHub Actions 배포와 실패 시 롤백 |

이 표는 제공된 소스 스냅샷의 구성이다. 운영 서버의 모든 버전·설정이 동일하다는
검증은 아니다. 발표 자료는 PPT/PDF를 그대로 임베드한 형태가 아니라 전용 코드로
구성되어 장 내부 단계, 그래픽 및 동기화 기능을 제어한다.

## 어떤 AI 도구를 사용했는가

소스 README 10절에는 **개발 전 과정에 Anthropic Claude Code를 사용했다**고
명시되어 있다. 이는 작성자의 사용 기록이며 화면만 보고 추측한 결과가 아니다.
기획 범위와 데이터·평가 설계의 판단은 사람이 정했다고 설명한다.

제품 내부에서 호출하는 LLM은 개발 도구와 별개다.
`src/lib/llm/registry.ts`는 `@earendil-works/pi-ai`의 제공자·모델 목록을 사용하며,
Anthropic·OpenAI·Google을 우선 표시한다. `models.ts`는 저장된 provider/model 및
에이전트 등급 설정으로 모델을 결정한다. 따라서 **실제 운영에서 사용 중인 특정
모델은 공개 화면이나 소스의 제공자 목록만으로 확정할 수 없다.**

README와 공개 설명에 따르면 취약점 조치 판정은 규칙·결정표가 담당하고,
AI는 조사·제안·서술을 담당한다. 이 분석에서는 실제 판정 정확도를 재평가하지 않았다.

## SuanLab에 적용한 부분

문제와 전문 분야를 먼저 보여 주고, 연구 논문·프로젝트·교육 자료로 이어지는 동선을
강화했다. 발표 모드는 Markdown 원고 하나로 읽기와 슬라이드를 생성하며,
키보드·직접 링크·전체 화면·노트·인쇄를 제공한다. AI 입문 강의에서 코드·수식·그림을
포함한 10장 시범 자료로 검증했다.

서버 동기화, 보안 점검 도메인, 3D 연출을 그대로 도입하지는 않았다. 현재 SuanLab은
GitHub Pages 정적 내보내기 구조이므로, 전용 서버가 필요한 기능보다 연구 자료의
정확한 연결과 읽기·발표 경험 개선을 우선했다. 참고 소스 코드는 복사하지 않았다.
