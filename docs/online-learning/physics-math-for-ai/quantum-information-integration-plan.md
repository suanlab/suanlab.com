## 다음 구현 게이트

1. **입력 소유권 — 준비 완료:** [아홉 가족의 입력·계산 연결](quantum-information-input-status.md)을 구현하고 검증했다. 아래는 유지할 계약이다. 아홉 가족의 wire 스키마와 검증 결과를 분리한다. 배열 구멍·알 수 없는 키·잘못된 정수·영 norm·비물리 상태·계수 예산을 거부하고, 내부 계산에서 커진 유리수를 외부32자리 예산으로 다시 거부하지 않는다. 원본 입력과 편집 중 잘못된 초안을 구분한다.
2. **응답 검증 — 아홉 가족과 통합 진입점9/9 준비:** [독립 응답 검증](quantum-information-capacity-response-status.md)을 이어서 구현했다. 아래는 전체 가족에 적용할 계약이다. 출력 모양만 확인하지 않는다. 요청과 가족·원시 입력의 일치를 확인하고, 행렬 좌표·스펙트럼·확률 합·부호·조건부 불가 상태·수치 구간의 수학적 관계를 독립적으로 대조한다. 계산 결과가 맞더라도 다른 요청에서 온 응답이면 거부한다. 변조 검사는 수치값·구간·행렬 좌표·정확 분류를 각각 바꿔 본다.
3. **Worker 수명주기 — native 준비:** [실제 Worker·React 검증](quantum-information-worker-status.md)을 마쳤다. 생산 reader 검증은 등록 뒤 별도 수행한다. 다음 계약을 구현했다. 순서가 바뀐 응답·취소·입력 교체·오류/재시도·문서 비활성·컴포넌트 해제를 처리한다. 브라우저의 실제 Worker에서 CLI 참조와 같은 입력을 대조한다. fixtures와 Python은 클라이언트 번들에 넣지 않는다.
4. **교수 화면 — 아홉 가족9/9 준비:** [아홉 번째 학습 화면 검증](quantum-information-capacity-teaching-status.md)을 마쳤다. 다음은 격리 등록 후보·실제 reader/생산 자산 검증이다. 다음 계약은 전체 아홉 단원에 적용한다. 각 단원에 직관 그림·개념 단계·예측·대표 예제·자유 실험·안내·해설 퀴즈를 작성한다. 무한대·비유일성·영 확률·비교 불가능성·반올림된 작은 양의 값을 정상 상태로 설명한다. 2D/SVG가 정확한 비교에는 그것을 쓰고, Bloch/회로의 공간적 이해에는 기존 Three.js의2D 대체·해제 동작을 재사용한다.
5. **학습 경험:** 기존 홈페이지 색·타이포·한영·명암을 유지한다. 키보드·320px·접근성·축소 모션·가시성 중단·잘못된 저장 데이터·저장 실패·새로고침 복원을 실제 브라우저에서 검사한다. 구현 세부사항을 학습자 흐름에 노출하지 않는다.

7. **생산 reader:** Next 정적 출력의 실제 JS/Worker/Three 자산과 한영 읽기·목차·실험·퀴즈·진입/활성 메뉴를 검증한 뒤 작업본에 반영한다. **도서 → Interactive Book**을 유지하고 Online Book 목록에는 교재 카드를 추가하지 않는다.
