# Coarse graining: 두 가족의 Worker 계산 연결

2026-11-08. [두 모형·한영 원고](coarse-graining-two-families-foundation-status.md)에 요청·응답 계약, 계산 Worker, 요청 수명주기 제어와 React 계산 hook을 연결했다. **교수 화면과 실제 교재 읽기는 아직 미등록**이다. 등록548단원·1644안내, 원래299/362입문 검증·63미완료와 전체51영역509주제·연구 깊이·공용 그림 후속 범위를 유지한다.

## 입력과 응답

`learning-coarse-protocol.ts`는 이산 Markov 집계와 연속 숨은 변수 소거의 입력을 구별하고 정수·분모·배열·모형 범위를 검사한다. JSON의 원래 숫자 토큰도 검사하므로 소수나 극단적인 지수가 정수로 반올림되어 들어오는 것을 허용하지 않는다. 초기 무게 배열까지 복사·동결하고 정규 순서의 입력 키를 사용한다.

응답은 전체 필드, 기록 순서·길이, 현재 기록, 요청 식별자·입력 키·모형, 정확한 준비 행렬과 분류를 검사한다. 구간의 순서와 숫자 표시도 대조한다. 이 검사는 전달 형식과 준비 일치를 확인하며 임의 송신자의 동역학을 증명하지 않는다. 수치식의 근거는 별도 독립 참조 검사다.

연속 모형의 비이진 유리수 초기값은512bit 방향성 구간으로 표현될 수 있다. `2/3` 등의 초기값을 양 끝점과 같다고 요구하던 오류를 고쳐, 원래 유리수를 포함하는지 검사한다. 실제로 다른 초기 구간은 계속 거부한다. 생산 수치 모형이나 독립 참조를 바꿔 검사에 맞추지 않았다.

이산 갱신에는 물리적 초 단위 시각을 붙이지 않는다. 음수가 되는 잘린 기억 근사도 확률이라고 바꾸거나 자르지 않는다. 연속 가족의 극단적으로 작은 초기 강제는 해석적 부호·로그·정밀도 미해결 표시를 유지하며 구조적0과 구별한다.

## 계산 수명주기

요청별 Worker 하나를 생성하며 새 준비·취소·완료·오류·unmount에서 종료한다. 이전 요청의 늦은 응답은 새 결과를 덮어쓰지 못한다. 오류 후 재시도와 생성 불가 상태를 구별하며 주 스레드의 동기 계산으로 대체하지 않는다. React hook은 현재 입력 키와 일치하는 결과만 노출한다.

## 확인한 근거

- 기존 두 모형·집필92검사와 새 전송·수명주기78검사, 합계170검사 통과.
- 타입 검사와 전체 lint 통과.
- 실제 Chromium Worker에서 두 가족의 독립 참조 입력69개를 전송·계산·응답 검증.
- 시작 직후 취소2회, 실제 controller의 취소2회·교체·의도한 Worker 오류 후 재시도·dispose 확인. controller 생성7개·종료7개·잔존0개.
- 브라우저 의존성 그래프에서 수치 엔진 제외 확인. 수치 엔진은 Worker에만 포함된다.

이 브라우저 검사는 실제 원본 Worker를 번들해 기존 로컬 페이지의 같은 출처에서 실행했다. 새 Next.js 산출물이나 새 교재 화면을 검증한 것은 아니다. 기존 정적 출력은 유지하며 새 빌드·공개 배포·commit·push는 수행하지 않았다.

다음은 두 가족의 비교 예제·고정 개념·자유 조작·해설·퀴즈·모션 정지·저장 복원이다. 이어 **도서 → Interactive Book**에서 한영·명암·모바일·키보드/터치·접근성과 정적 출력을 확인한 후 입문 완료를 기록한다. 비평형 영역 종합 점검과 양자역학 이후 순서, 일반 비선형 사영·재규격화 등의 연구 범위도 남는다.
