## 복소 미분과 켤레 경로

실수 전미분을 a·h+b·conj(h)+o(|h|)로 분해하여 b=0일 때의 복소 미분 충분성을 증명했다. 실수값 함수 x³y/(x⁴+y²), f(0)=0은 연속이고 원점 CR이 성립하지만 직선 t·it의 몫 극한 0과 곡선 t+it²의 극한 1/2이 다르다. 앞선 전미분 단원과 연결하여 누락된 실수 미분 가정을 확인하게 했다.

s=az+b·conj(z), L=|s−c|²의 gradient는 2(conj(a)r+b·conj(r))이다. 실수 내적의 수반으로 일반 하류 gradient 전달식도 유도했다. a=1,b=1/2,c=1+i,z=1+i에서 η=1/4의 새 매개변수는 5/8+9i/8, 새 손실은 25/128이다. 최소점은 2/3+2i이며 모든 초기값의 수렴 범위는 0<η<4/9이다. 세 고정 층·세 매개변수 점을 실수·허수 중앙차분으로 검산했다.

## 유수와 수치 해상도

ρ=a/R≥0인 단순극의 정규화 중점 구적은 Q_N=1/(1+ρᴺ)이다. 안팎의 수렴 급수와 이동한 단위근의 합으로 유도했다. 유효한 적분은 ρ<1에서 1,ρ>1에서 0이다. ρ=1의 원시 유한 합 1/2은 보통 경로 적분을 정의하지 못하며 생산 실습은 여전히 경로 위 극을 거부한다.

N=32·128·512, ρ=0.99·1.01의 비교표와 정확 분수 계산을 추가했다. 정규화 오차 ε를 만족하는 N의 하한, ρ_N=exp(−c/N)에서 오차가 남는 비균등 수렴도 설명했다. 두 고유값 0.99·1.01의 대각 resolvent 사영을 성분별 유수로 계산하여 유한 구적 필터가 정확한 멱등 사영과 다른 점을 확인했다. 비정규 행렬의 일반 조건수 분석은 후속 범위다.

## 정확한 축과 수치 표현의 수정

검토 중 exp(1/z)의 작은 순허수 입력이 cos(π/2)의 잔차 때문에 잘못된 numeric-range가 되는 문제를 재현했다. 명시적인 ±90도와 ±180도는 정확한 사분면 좌표로 구성하고 근처의 다른 각도는 그대로 계산하도록 수정했다. 0.1·0.001·10⁻¹⁰⁰·10⁻²⁰⁰ 반지름의 두 순허수 축에서 유한 출력과 크기 1을 확인한다. 이는 큰 위상의 임의 정밀도 정확도를 보장한다는 뜻은 아니다.

음의 실수축의 exp(−1000)은 수학적으로 양수이지만 binary64에서 underflow한다. 기존의 [0,−0] 표시를 numeric-range로 구분했으며 원점 자체의 function-domain과 별도로 유지한다. 두 축 근처의 각도가 크기 1로 잘못 맞춰지지 않는지, 극단 반지름에서는 양·음 실수부의 overflow·underflow가 각각 범위 한계로 보고되는지도 검사한다. 한영 특이점 원고에도 이유와 표현 범위를 설명했다.

## 확인한 일차 자료

- [Trefethen·Weideman, 2014 저자 공개 PDF](https://people.maths.ox.ac.uk/trefethen/publication/PDF/2014_149.pdf): §3 정리 3.2와 aliasing 증명(인쇄 396–397쪽), §18 식 (18.1)–(18.3)의 resolvent 구적(446–447쪽)을 확인했다. 자체 이동 중점 예제와 대각 사영 계산을 원전의 전체 실험 재현으로 계산하지 않는다.
- [PyTorch 2.15 Gradcheck mechanics](https://docs.pytorch.org/docs/2.15/notes/gradcheck.html): 실수 손실의 복소 미분과 2×conjugate-Wirtinger 규약, 실수·허수 수치 차분 부분을 확인했다. 브라우저나 예제 코드에서 PyTorch 학습을 실행했다고 주장하지 않는다.

확인한 저자 PDF는 74쪽이며 SHA-256은 `378ed15ee9b822bc222dac0e90cacf689d56cc21be7710bbce715dd1e6d2324b`이다. 확인일은 2026-11-11이다.

## 실행 검증

복소 계산 검사 24개와 원고 보존 검사 7개, 총 31개가 통과했다. 추가한 aliasing 검사는 네 극 비율·세 반지름·세 노드 수·두 방향의 72개 생산 계산을 독립 유리식과 비교한다. 정확한 순허수 축, 음의 실수축 underflow와 원점의 정의역 구분, 축 근처 각도의 보존도 별도 검사했다.

복소해석 9개 등록 단원을 선택한 원고 공통 검사도 통과했으며 다른 662개 검사는 이 선택 실행에 포함하지 않았다. 두 언어의 수식·MathML·목차와 영어의 한글 혼입을 확인했다. 여섯 Python 예제를 실행했고 한영의 표시 수식도 문장 끝 구두점을 제외하고 일치함을 확인했다. 코드 실행 근거는 `.runtime/learning/complex-research-python.json`이다.

수정 후 TypeScript 검사와 정적 빌드가 성공했고, 1,888개 HTML의 내부 링크·자산·앵커·사이트맵·canonical 검사를 통과했다. 검토 원고 해시에는 이번 여덟 한영 파일을 명시적으로 추가하여 현재 32개 검토 원고의 정확한 전이만 허용한다. 추가 문구·알 수 없는 기준 해시·미등록 파일을 거부하는 검사를 유지하며 역사적 fixture는 변경하지 않았다.

최종 빌드의 `npm run check:complex`는 71개 한영·320/768/1440px·영어 다크 모드·주제 검색 상태와 상호작용 11개 묶음, 안내 예제 27개를 통과했다. 새 표·수식·Python 코드의 표시와 모바일 키보드 스크롤, 잘못된 정수 초안의 표시·계산 보존·Escape 복원, 정확한 순허수 축·음의 실수축 underflow·원점 정의역, 입력·완료 저장 복원을 확인했다. 페이지 실행 오류와 WCAG A/AA 위반은 0건이었다. 실행 근거는 `.runtime/learning/complex-browser.json`이다. 공개 반영은 GitHub Pages 배포 결과로 별도 확인한다.
