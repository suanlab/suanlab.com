# 공통 수치 입력 검증과 초기화 보완

2026-11-07. 열역학 점검에서 발견한 비영 입력의 0 변환 문제를 나머지 공통 `NumberField` 사용처 10개에도 수정했다. 적용 범위는 일반 실습 42그룹의 487경로와 별도 실습 26경로, 총 513개 읽기 경로다. 모든 경로를 개별 브라우저 검사했다는 의미는 아니다.

## 변경 내용

- 공통 순수 파서가 소수·과학 표기법, 유한 범위, 정수 제약을 검사한다. `1e-999` 같은 비영 값이 반올림으로 0이 되면 모델에 전달하지 않는다. 표현 가능한 작은 비영 값과 정확한 0은 허용한다.
- 정수 항목은 `2.0000000000000000001`처럼 Number 변환에서 소수 부분이 사라지는 입력도 거부한다. 입력 조절 간격 `step`과 정수 제약은 구분한다. 자유에너지의 에너지 간격·기준은 소수를 허용하고, 독립 복제 수는 정수만 받는다.
- 올바른 입력은 종전처럼 즉시 실습에 반영한다. 잘못된 초안은 이전 모델 값을 유지하고 Enter·포커스 이동 때 한영 안내를 표시한다. Escape는 현재 설정을 복원하며 프리셋·전체 초기화는 오류 초안도 지운다. 같은 프리셋을 다시 선택하는 경우도 포함한다.
- 벡터 입력과 비동기 앙상블 결과 화면에도 초기화를 전달한다. 언어 컨텍스트가 없는 정적 렌더링을 지원하되 기존 `useLanguage`의 필수 provider 규칙은 유지한다.
- 앞서 수정한 열역학 전용 입력도 같은 파서를 사용한다. 이 입력의 Enter·포커스 이동 후 적용 동작은 유지한다.

## 검증 범위와 근거

최초 공통 입력 수정 상태에서 전체 테스트 8,398개가 통과했다. 이후 정수 속성과 자유에너지 복제 수 제약을 보완했으며, 추가된 공통 파서 3개 테스트는 기존 전용 입력 2개와 함께 별도 5개 통과를 확인했다. 최종 자유에너지·교수 자료·입력 관련 검사는 49개 통과했다. 중복되는 검사를 더해 전체 테스트 수로 표시하지 않는다.

브라우저 점검은 68개 대표 단원의 한영·명암·폭 조합을 사용한다. 최초 132사례 통과 후 검증 코드가 `step=1`을 정수로 오인해 첫 자유에너지 화면에서 중단됐다. 이는 연속값 에너지 간격의 정상 입력을 정수 오류로 기대한 문제였다. 명시적 정수 속성으로 검증 코드를 고쳤고, 복제 수의 정수 제약을 명시한 최종 빌드에서 남은 28사례를 이어 검사해 통과했다. 두 에너지 연속값의 소수 입력도 한영 4회 확인했다. 앞선 132사례와 후속 사례의 빌드 범위는 구분해 기록한다.

대표 읽기 160사례와 기존 전용 입력 2사례가 통과했다. 비영 양수·음수 초안은 각각 160회·160회, 빈 입력·초기화·프리셋은 각각 160회, Escape는 320회, 정수 초안은 114회 확인했다. 과학 표기법 연속 편집·저장 1회, 오류 안내 언어 전환 2회, 결과 화면 입자 수 검사·초기화 8회를 포함한다. 전체 페이지 접근성 162상태에서 위반이 없었으며 생성된 Worker 48개가 모두 종료됐다. 페이지 오류는 없었다.

최종 빌드·타입 검사·1,771개 HTML의 정적 출력 검사가 통과했다. 이전 4,300개 기준 소스 중 변경 13개·추가 3개로 현재 4,303개를 기록했다. 수치 모델·등록 데이터·본문·스타일·메뉴의 변경은 없다. 최종 출력 4,294파일도 해시로 보존했다. 초기 빌드에서 새 검증 코드의 타입 추론 오류가 발견되어 명시적 타입으로 수정했고 최종 빌드에서 통과했다.

최종 결과는 `.runtime/learning/shared-number-field/verification.json`에 기록했다. 원본 로그·체크포인트·테스트·출력 및 소스 해시는 같은 디렉터리에 보존한다. 수치 모델·등록 데이터·원고·메뉴·스타일은 이전 기준과 비교해 보존을 확인했다. commit·push·공개 배포는 수행하지 않았다.
