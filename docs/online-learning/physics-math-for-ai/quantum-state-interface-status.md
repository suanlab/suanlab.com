# 양자 상태·Hilbert 공간: Worker와 개념·자유 실험 화면

2026-11-08. [두 수치 가족·한영 원고](quantum-state-foundation-status.md)에 입력·Worker·교수 화면을 연결했다. **실제 Next.js 교재 읽기는 아직 미등록**이다. 등록550단원·1650안내, 원래300/362입문 검증·62미완료, 전체51영역509주제와 연구 깊이·공용 그림 후속 범위를 유지한다.

## 학습 화면

| 가족 | 고정 비교와 안내 | 자유 실험과 시각화 |
| --- | --- | --- |
| 복소 상태·ray·기저 진폭 | 같은 Z 확률·다른 ray, 전역 위상과 대표 거리, Gram 기하 | 준비10개, 복소 원시 좌표·기저·위상·배율16개 정수 칸, Bloch 3D/2D·진폭·확률 비교 |
| 파동함수·L² 사영·완비성 | 샘플과 bin 확률, 포착 norm과 재정규화, 영 사영·동치류 | 준비11개, 함수·분할·길이·차수·bin·샘플15개 정수 칸, 복소 진폭·밀도·정확 질량·오차·계수 표 |

각 가족에 세 개념 단계와 예측·해설을 넣고 같은 비교를 자유 실험으로 옮기는 안내를 제공한다. 고정 비교와 저장된 자유 실험의 준비를 분리한다. 계수와 정규화 근거는 정확 유리수·방향성 구간으로 확인한다.

순수 C² 상태의 Bloch 구는 실제 Worker의 좌표를 사용한다. Three.js 그림은 드래그·시점 버튼으로 카메라만 바꾸며 자동 회전이나 물리 시간 진화를 만들지 않는다. WebGL을 사용할 수 없거나 사용자가2D를 고르면 같은 좌표의 두 투영을 제공한다. 변환 전후의 복소 진폭과 기저 확률은 별도로 비교한다. 영 진폭의 위상을0으로 정하지 않고 정의 조건을 표시한다.

L² 그림의 횡축은 물리 위치이고, 차수 진단은 다항식 차수다. bin 질량은 정확 적분값이며 샘플 수로 바꾸지 않는다. 점 사이의 선은 표시용 안내이고 source 조각 경계를 가로질러 잇지 않는다. 유한 사영의 포착 질량을 유지하며, 재정규화 값은 별도다. 영 사영에서는 정규화와 fidelity가 미제공이다.5초 샘플 스캔은 위치 표식을 훑는 표시이고 양자 시간 진화가 아니다. 모션 정지·시스템 동작 줄이기·화면 밖에서는 자동 진행하지 않으며 수동 선택은 유지한다.

## 전송과 복구

`learning-hilbert-protocol.ts`는 두 입력의 전체 소유 필드·정수 범위·원래 JSON 숫자 토큰을 검증하고 복사·동결한 정규 입력 키를 사용한다. 응답은 모형·요청 ID·입력 키, 전체 구조와 배열 길이·순서, 숫자 표시·구간·확률 합·사영 질량·재구성 근거의 형식을 검사한다. 이 검증은 임의 송신자의 동역학을 증명하는 것이 아니며, 생산 수학은 별도 독립 참조와 대조한다.

계산은 Worker에서만 실행한다. 새 준비·취소·완료·오류·unmount에서 소유 Worker를 종료하고 늦은 응답이 새 준비를 덮어쓰지 못하게 한다. 실패 후 재시도를 제공하며 주 스레드 동기 계산으로 대체하지 않는다. 저장 복원 후 쓰기를 시작하고, 손상된 저장값은 기본 준비로 복구한다. 저장 불가 상태에서는 현재 방문의 실험을 유지한다.

## 확인한 근거

- 기존 수치·집필61검사, 새 전송·수명주기53검사, 교수 화면·SSR·의존성6검사, 합계120검사 통과. 타입·전체 lint 통과.
- 실제 Chromium Worker에서 독립 참조 입력46개, 시작 직후 취소2회와 controller 취소·교체·의도한 오류 후 재시도·dispose 확인. controller 생성7개·종료7개·잔존0개.
- 한영×명암×320px/1600px×두 가족의16화면·접근성16조합. 영어 한글 잔류·가로 넘침·화면 오류 없음.
- 준비42회 선택, 개념 단계·예측 각12회, 잘못된 입력20회, 저장 복원16회.
- Worker 실패 후 재시도·손상 저장값·저장 쓰기 실패 각4회, 모션6회 확인.
- 실제3D 표시8회, WebGL 상실 후2D 대체와3D 재시도2회 확인. 화면 검사 Worker 생성268개·종료268개, 최종 unmount 뒤 canvas 잔존0개.
- 전체 화면 의존성 그래프에서 두 수치 엔진과 정규화 core가 주 스레드에 들어오지 않음을 확인. 명암·좁은 화면 캡처를 검토하고 Bloch 3D를 별도로 점검했다.

이 검증은 원본 컴포넌트·실제 공급자·실제 Worker를 기존 로컬 서버의 같은 출처에서 실행한 것이다. **새 Next.js 읽기와 생성된 정적 Worker 자산을 검증한 것은 아니다.** 기존 수치 모형·참조·원고와 등록 교재·정적 출력은 유지한다.
