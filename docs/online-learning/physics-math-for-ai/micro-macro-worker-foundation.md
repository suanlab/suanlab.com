# 미시·거시 상태 계산의 Worker 기반

2026-11-06. 세 가족의 계산·한영 본문을 실제 실험 패널에 연결하기 위한 비동기 계산 기반을 구현했다. 모델은 수정하지 않았다. 실험 패널·그림·교육 메타데이터·단원 등록과 실제 Next 읽기 화면은 아직 미완료다.

## 요청과 계산의 분리

공유 프로토콜은 세 가족의 입력을 구분하고 모델 타입만 가져온다. binary N≤4096,가중 분할32상태/32군,잡음 채널16입력/16출력의 입력 계약을 가볍게 검증한다. 확률0인 행·군과 누락된 배열 원소를 무의미한 기본값으로 고치지 않는다.

실제 모델 import와 평가는 Worker 쪽 dispatch에만 있다. UI용 factory는 [webpack의 literal Worker URL 형식](https://webpack.js.org/guides/web-workers/)을 사용한다. 반환 결과는 원래 모델의 문자열·숫자·배열로 직렬화된다. 버전·요청 ID·가족·결과 scope를 확인하며,오류를 일반 입력 오류·계산 실패 등으로 구분한다. 결과 본문의 모든 필드를 별도 비신뢰 스키마로 재검증하는 공개 API는 아니다. 같은 빌드가 소유한 Worker의 결과를 처리한다.

입력은 깊은 불변 스냅샷으로 보존한다. 키는 유효 매개변수 순서를 고정해 만들므로 호출자의 객체 재생성·속성 순서·무관한 필드 때문에 같은 계산을 반복하지 않는다. React 훅은 입력이 바뀐 렌더에서 기존 결과를 새 매개변수의 결과로 노출하지 않는다.

## 중단과 수명 주기

활성 요청 하나마다 Worker 하나를 사용한다. 새 요청·취소·비활성화·화면 해제는 기존 Worker를 종료하므로 긴 계산 뒤에 새 요청을 줄 세우지 않는다. 요청 ID뿐 아니라 소유 Worker와 활성 토큰도 검사해 캡처된 늦은 callback이 새 상태를 덮지 못하게 한다.

시작 대기와 실제 계산 시작을 구분하는 확인 메시지를 제공한다. 완료·오류에서는 handler를 제거하고 Worker를 종료한다. React Strict Mode의 setup/cleanup,취소 후 재시도,입력 사용 여부 변경도 처리한다. Worker 생성/로드 실패에 무거운 계산을 메인 스레드에서 직접 실행하는 fallback은 없다.

## 단위·회귀 검사

15개 검사가 세 모델의 실제 dispatch·직렬화,잘못된 요청/입력,불변 스냅샷,완료 정리,이전 요청 중단과 늦은 callback,ID/가족/version/scope 오류,생성/전송/실행/메시지 오류,취소·dispose·재생성,재진입 취소,계산 시작 확인과 정규 키를 다룬다.

기존 세 가족·본문·공유 산술과 합친251개 검사가 통과했다. 타입 검사와 대상 lint도 통과했다. 모델·본문의 이전 증거 해시는 진행 기록을 갱신하기 전에 모두 일치함을 확인했다. 기존 통합 소스·자산·검사3888개와 정적 출력4236개도 보존한다. 새 파일이 추가되었으므로 전체 소스 집합 크기가3888개라는 뜻은 아니다.

## 실제 브라우저와 webpack 자산

`node scripts/check-micro-macro-worker.mjs`는 격리된 webpack 빌드에서 실제 factory·Worker entry·React 훅을 묶는다. 별도 해시 Worker JS 자산1개가 생성되고,세 계산 함수가 Worker에만 있으며 메인 번들에는 없음을 확인한다. 임시 서버와 소유한 headless 브라우저는 검사 후 종료한다. 기존4175 미리보기는 건드리지 않는다.

React Strict Mode에서 세 모델의 완료,실제 계산 시작 뒤의16×16 긴 계산 중 클릭과 heartbeat,새 입력으로 교체,사용 여부 변경,취소/재시도,화면 해제/재생성,전체 긴 계산 완료,Worker 자산 요청을 차단한 로드 오류와 복구를 검증했다. 입력 객체를 매 렌더마다 다시 만들고 계산 중 부모 화면도 갱신해 불필요한 Worker 재시작을 확인한다.

최종 실행은 Worker 자산 요청14회,heartbeat396회,관측된 최대 heartbeat 간격38ms였다. 오래된 결과 노출·남은 Worker·런타임 예외는0이며 복구 뒤 시작/종료 수가 일치한다. 이 값은 격리된 검사 환경의 관측이며 전체 홈페이지의 응답성 보장이 아니다. 근거는 `.runtime/learning/micro-macro-worker/browser/result.json`이다.

## 남은 통합

이 검사는 실제 webpack 자산과 브라우저 Worker 동작을 확인했지만 Next 정적 export·실제 읽기 경로의 자산 로딩 검증을 대신하지 않는다. 다음은 이 훅을 사용하는 세 실험 패널·도표·대표 그림과 가족별4개 개념·3개 안내·2개 질문이다. 입력 변경을 모으는 조작 설계와 친절한 진행/재시도 표시도 패널에서 마무리한다.

이후 실제 Interactive Book 경로에서 전체 빌드·정적 출력·한영·명암·모바일·접근성·저장·모션과 긴 계산 응답성을 검증한다. 등록509단원·1527안내 및 입문 검증282주제·미완료80주제는 유지한다. 현재 근거는 `.runtime/learning/micro-macro-worker-verification.json`,전체 통합 계약은 [읽기 화면 통합 계획](micro-macro-integration-plan.md)이다.
