## 모형과 관측 계약

`src/lib/learning-hastings-proposal.ts`는 양의 목표 정수 가중치3개와 시계·반시계·머무름 제안 가중치로 고정 커널을 분석한다. 목표는1..1,000,000, 제안은0..1,000,000이며 제안 합은 양수다. 희소 배열·영 목표·비정수·비유한 입력을 거부하며 입력을 바꾸지 않고 동결된 사본을 반환한다. 초기 경로나 시간 순회를 생성하는 모형은 아니다.

기존 정확한 유리수 helper를 사용한다. 제안이 없으면 조건부 수락은null, 제안은 있으나 역제안이 없으면 정확한0이다. 자기 자신 제안은 존재할 때만 수락1이다. 수락·거부의 무조건부 기여와 최종 출발 대각을 따로 제공한다. 대각에는 자기 자신 제안과 모든 거부가 들어간다.

보정하지 않은 목표 비율 비교도 명시적으로 반환한다. 의도한 목표에서의 흐름·한 단계 변화와 실제로 푼 정상분포·정상 흐름을 구별한다. 정상해는 정확한 행 소거로 풀며 비유일한 정상분포 가족을 임의의 한 분포로 바꾸지 않는다. 그래프 도달성과 귀환은 정확한 양수 여부로 판정한다. 수락률은 자기 자신 제안을 포함하고 이동률은 제외한다. 목표 준비 평균과 실제 정상 평균도 구별한다.

모든 머무름을 없앤 상태 변화 점프 체인의 전이·정상법칙도 제공한다. 실제 정상분포에 상태별 이동 확률을 곱해 정규화한 분포이며, 일반적으로 원래 목표와 다르다. 항등 커널의 점프 법칙은 미제공이다. 모든 확률·잔차·흐름·거리·수축 계수는 정확한 BigInt 유리수이고, 소수·크기 로그는 표시 투영이다.

## 본문과 교육 내용

한영 각각16절·19수식·표4개·해설 문제6개다. 쌍별 흐름의 최솟값에서 수락식을 유도하고, 제안·조건부 수락·최종 전이를 나눈다. 거부를 출발 대각에 돌려놓는 이유와 제안의 기약성이 보정 후에도 유지되는지 확인하는 이유를 설명한다.

- 목표(1,2,4), 제안(2,1,1): 보정하지 않으면 목표 변화(0,−1/28,1/28), 실제 정상분포(1/7,5/21,13/21), 목표 거리1/21이다.
- 목표(1,1,4): 비대칭 제안을 보정하지 않아도 우연히 목표를 보존하지만 순환 전류1/24가 남는다. 제한된 성공 예만으로 일반 규칙을 검증할 수 없다.
- 한 방향만 제안: 올바른 보정이 전부 거부하여 항등 커널이 될 수 있다. 목표 보존·유일성·탐색을 나눈다.
- 머무름 삭제: 올바른 보정 커널도 점프 기록에서는(3/14,3/7,5/14)을 보이며 원래 목표와 다르다.

원 논문의 [공개 PDF](https://hedibert.org/wp-content/uploads/2013/12/1970Hastings.pdf)2.2절에서 제안 구성·검사 비율·기약성 확인 조건을 대조했다. 원 논문 전체나 모든 일반화를 검토했다는 주장은 아니다. 이 프로젝트의 특정 유한 모형, 수치 예와 점프 법칙은 직접 유도하고 독립 유리수 계산으로 확인했다. 자세한 유도는 [노트](hastings-proposal-derivation-notes.md)에 정리했다.

## 검증과 보존

새 모델57개·본문6개, 합계63개 검사와 기존 산술·첫 가족·등록 보존 회귀127개가 통과했다. 독립 Python `Fraction` 기준42설정의 **8,970개 정확한 관측**을 분자·분모·부호·표시 투영으로 비교했다. 기본 제안·수락·거부 사건의 열거는756개 도착 확률 비교를 제공한다.

기준은 쌍별 흐름의 최솟값에서 전이를 구성하고, 루트를 향하는 유향 생성 트리를 열거해 실제 정상법칙을 구한다. 런타임의 유리수 행 소거와 다른 계산이다. 기준의 rank는 소행렬식으로, 통신은 DFS로, 주기는 단순 순환 길이의 gcd로 계산하여 런타임의 행 소거·도달성·귀환 지지집합 거듭제곱과 대조한다. 점프 정상법칙도 별도 트리 합과 이동 가중 공식으로 서로 확인한다.

추가로 목표 가중치1..3, 제안 가중치0..2의 영합을 제외한702설정을 검사했다. 보정 후 보존·상세평형·통신·수렴 조건, 보정 전의 우연한 보존과 주기를 판별한다. 이것을0..1,000,000의 전체 범위를 전수 검사한 것으로 부르지 않는다.

기준의 바이트 재생성, lint·타입 검사도 통과했다. 기존4,209소스와4,280정적 출력은 유지했다. 이번에는 전체 테스트·빌드·실제 브라우저 등록 검사를 다시 실행하지 않았다. 직전 등록 통합의8,005개 전체 검사와 이번190개 준비/관련 검사 범위를 구별한다. 근거는 `.runtime/learning/hastings-proposal/verification.json`과 같은 폴더의 상세 기록이다.
