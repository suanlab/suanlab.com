# Quantum circuit·channel: Worker execution foundation

2026-11-09. [앞 단계의 정확 관측·독립 검증](quantum-circuit-response-status.md)을 계산/검증 Worker와 취소 가능한 컨트롤러로 연결했다. **등록0/4이며 학습 화면·실제 reader·Next production 자산 검증은 남아 있다.**

## 구현

- 정확 분수 문자열·밀도행렬·게이트·가중 연산자·측정 갈래의 읽기/저장 형식과 소유권 검사. 입력 크기·정수 토큰·중복 키·프로토타입·getter를 검증한다.
- 계산 Worker가 결과를 만들고 별도 검증 Worker가 원래 입력과 모든 관측값을 재계산한다. 요청 ID·종류·입력 key를 함께 확인한다.
- 컨트롤러가 검증된 응답만 수용한다. 큰 응답 복사는 짧은 작업으로 나누고, 취소·입력 교체·dispose·시간 초과 시 Worker를 종료한다. 실패 후 재시도도 지원한다.

정확 입력의 실행 제한과 `ready`의 의미, 오류 종류, 메시지·소유권·취소 규약은 [Worker 계약](quantum-qubit-worker-contract.md)에 기록했다. 물리적이지 않은 사상을 올바르게 계산한 결과와 잘못된 입력/계산 결과를 구별한다. 메인 컨트롤러에는 수학 엔진을, 검증 Worker에는 제품 계산기를 포함하지 않음을 번들 그래프로 확인했다.

## 검증 근거

새 **625검사**는 프로토콜603개와 컨트롤러22개로 구성된다. 기존 수치·한영 본문·유니터리 **1199회귀 검사**, 타입 검사와 lint도 통과했다. 기존 독립 참조595준비를 새 요청 형식으로 계산·검증하고, 매 준비에서 올바른 스칼라 형식을 유지한 잘못된 값도 거부했다. 구조적으로 그럴듯한 응답이라도 수학적 검산을 생략할 수 없다.

실제 브라우저에서는 회로91·채널216·환경45·instrument234·측정 지연9준비의 계산 결과와 검증 후 결과를 각각 기준 해시와 비교했다. 이 probe의2개 Worker를 종료했다. 별도 컨트롤러 검사에서 생성한32개도 모두 종료했고 활성 Worker는0이었다. 다섯 종류의 유효 형식 스칼라 변조, 계산/검증 대기 중 취소, 입력 교체, 시간 초과, 시작 실패와 재시도를 확인했다. 계산 중 타이핑과 타이머 간격은 `.runtime/learning/quantum-qubit-workers/native-workers.json`에 측정값으로 남겼다.

브라우저 검사는 로컬 Blob module Worker에서 수행했다. 실제 reader·Next 자산이나 숨긴 탭 동작까지 검증했다고 확대하지 않는다. 최종 소스/증거 보존과 정적 출력 불변, 모든 로그·번들 의존성의 근거는 `.runtime/learning/quantum-qubit-workers/verification.json`에 기록한다.
