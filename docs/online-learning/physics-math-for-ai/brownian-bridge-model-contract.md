# Brownian bridge와 시간 분할: 계산·검산 계약

2026-11-10. 원래 경로적분 입문 주제의 첫 처리 `brownian-bridge-time-slicing-measure`다. 이 계약은 고정끝 유한 Gaussian bridge만 정의한다. Euclidean potential·안장 근사·실시간 위상과 원주제 감사는 후속 처리다.

## 입력과 관측

입력은 `intervals,time,diffusion,start,end,probe,source` 일곱 필드다. N=`intervals`는 구간 수2…32이며 자유도는N−1이다. τ=`time`와D=`diffusion`은 양수이고≤16, 양끝a,b와 점 원천j의 절댓값은≤16이다. 유리수 문자열의 분자·분모는 각각12자리 이내이며 지수 표기·소수·공백·음의0·0분모를 받지 않는다. 원래 분수 표기를 유지한다. 선택 시각은 정수`probe`=0…N이다. N=2의 유일한 내부 노드는 양끝 힘을 모두 받는다.

보조 원천은 무차원 지수j x_probe에 결합한다. 따라서 j의 단위는 위치의 역수이며 물리 에너지 원천과 동일하지 않다. 양끝의 원천은 상수만 더해 정규화하지 않은 커널의 무게를 바꾸고 조건부 분포는 바꾸지 않는다. 나머지 입력은 고정하고 이 한 점 원천만 변화시킨다.

## 정확한 유한 법칙

δ=τ/N이며 증분 밀도는 exp[−(Δx)²/(4Dδ)]/√(4πDδ)다. 중간 값들을 적분하면 전체 시간 자유 커널이 되고, 이를 나누면 고정끝 조건부 법칙이다. 밀도와 정확한 끝점 사건의 확률을 혼동하지 않는다.

내부 Q=L/(2Dδ), μᵢ=a+(b−a)i/N, Cᵢⱼ=2Dδ[min(i,j)−ij/N]이다. 표시용 전체 공분산은 양끝의0행/열을 포함한(N+1)×(N+1)이다. 이차 에너지에는 고정끝 간선이 들어가므로 첫·마지막 내부 대각도2다. 영모드 제거나 평균0 제약을 추가하지 않는다.

점 원천으로 μ가 j C[:,probe]만큼 바뀌고 C는 그대로다. 로그 생성함수는 j μ_probe+j²C_probe,probe/2다. 생산 계산은 닫힌 Green 식을 사용하며 Q C=I와 Q μ의 힘 잔차를 정확분수로 확인한다. 삼중대각 LDL의 대각·하부 한 줄과 행렬식을 함께 돌려준다.

자유 커널의 prefactor는 π를 제외한 제곱인1/(4Dτ)와 해석적 식으로 남긴다. 지수의 유리수 계수는 정확하다. π·제곱근·지수의 소수 구간이나 실제 kernel 값을 수치 인증했다고 주장하지 않는다.

## 관측량과 정련

사다리꼴 면적은 고정 양끝의 절반 가중치와 내부 가중치δ를 사용한다. 원천을 포함한 평균, 변하지 않는 분산Dτ³(1−1/N²)/6, 해석적 극한 분산과 차이를 제공한다. 증분 평균·전체 증분 공분산, 기대 제곱 합과 기대 작용도 별도로 제공한다. 원천이 없는 기대 작용은 양끝 변위 항+(N−1)/2다.

정련은 N,2N,4N,8N에서 같은 전체 시간·확산·양끝·물리적 원천 시각과 세기를 유지한다. 예전 시각의 주변분포는 정확히 일치한다. 면적 관측량은 달라지므로 분산과 오차는 바뀐다. 최고256구간의 행은 해석적 비교이며 실제 전체 행렬은 입력N≤32에서만 계산한다. 연속 측도의 존재 증명이나 임의 potential의 수렴 보증이 아니다.

## 독립 검산과 통신

Python 참조는 시간 발생 행렬의 Gram, 정확 Gauss–Jordan 역행렬·pivot 행렬식, 끝점 힘을 이용한 평균, 완전제곱의 차이와 증분 선형 관측량으로 재구성한다. 브라우저 독립 검산도 별도 유리수 산술·발생 행렬·소거·증분 가중합을 사용한다. 생산 모듈과 생산 산술은 runtime 의존성에 없다.

불신 응답의 분수 문자열은 산술에 투입하지 않는다. 유효한 소유 입력에서 기대 결과를 계산하고 bounded descriptor 복사를 거친 후보 전체와 비교한다. 잘못된 원천·정규화·면적·정련·범위 주장과 추가/누락 필드도 거부한다. 기대 결과 cache는 원래 입력 문자열을 키로4항목만 유지하며 반환값은 별도의 불변 복사다.

요청 키는 필드 삽입 순서를 정규화하지만 원래 분수 문자열은 보존한다. 같은 필드를 다른 순서로 받은 경우도 hook/controller가 같은 결과로 인식하며, 잘못된 hook 입력은 Worker를 만들지 않고 오류를 보고한다.

버전1·양의 안전한 정수requestId·단원kind·원래 입력·inputKey와 결과 내부 입력이 모두 일치해야 한다. 한 요청이 계산 Worker와 별도 검산 Worker를 소유한다. main thread hook에는 수학 계산기를 넣지 않으며, 결과 복사 중 취소/교체도 허용한다. 종료·기한 초과·숨김/복귀·재시도 시 이전 결과가 새 입력의 결과로 보이지 않아야 한다.
