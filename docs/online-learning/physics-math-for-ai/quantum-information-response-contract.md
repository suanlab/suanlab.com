# 양자정보 독립 응답 검증 계약

2026-11-09. 아홉 가족의 독립 응답 검증 **9/9**와 통합 진입점 `validateQuantumInformationResponse`를 준비했다. 가족별 검증 함수는 아래 각 절의 계약을 따른다. 원래 입력을 소유한 뒤 kind별 검증기로 전달하며 수치 관측/정확 계수 수를 공통 형식으로 반환한다. [실제 module Worker·React 연결](quantum-information-worker-status.md)은 준비됐으며 reader 등록/생산 자산 검증은 아직 없다.

## 소유권과 요청 일치

응답은 기존 descriptor-only wire copier로 소유하고 깊이 동결한다. getter·순환·비정상 prototype·비유한 숫자·배열 구멍을 거부한다. envelope는 `schemaVersion`, `kind`, `input`, `result`만 허용한다. 원래 요청의 raw input key가 일치해야 하므로 수학적으로 같은 `1/2`와 `2/4`도 다른 요청으로 취급한다.

아직 메시지 순번/Worker 수명주기 protocol은 없다. 현재 검증은 **원래 입력과 결과의 일치**이며, 같은 입력을 반복한 비동기 요청의 순번 관리를 대신하지 않는다.

## 판별 수학의 독립 경로

검증기는 생산 판별기·계산 진입점·생산 제곱근·fixtures를 호출하거나 import하지 않는다. 유리수 사칙연산과 관측 표시 formatter만 공용 primitive를 사용한다.

1. 원래 Bloch 입력에서 두 Hermitian 밀도행렬을 만들고 대각/행렬식으로 물리성을 확인한다.
2. 가중 차이 행렬의 trace·determinant와 특성방정식으로 두 고유값의 대수적 증명서를 만든다. 고유값의 정확한 부호로 전략·영 고유값·비유일성을 분류한다.
3. 양의 고유공간 사영 `(Delta-lambda_minus I)/(lambda_plus-lambda_minus)`에서 효과 행렬과 축을 구성한다. 생산기의 Bloch 축 나눗셈을 재호출하지 않는다.
4. 효과와 각 밀도행렬의 trace로 조건부 확률·달성 성공률을 확인한다. 거리 제곱은 차이 행렬의 determinant, 제곱 fidelity는 `Tr(rho sigma)+2 sqrt(det(rho)det(sigma))`로 확인한다.
5. 모든 값은 `a+b sqrt(c)` 꼴의 유리수 증명서다. 보고된 구간의 끝점과 비교할 때 제곱근을 근사하지 않고 부호·제곱의 정확한 비교를 쓴다.

프로젝터 응답의64개 관측 좌표(상수 판정은61개), 행렬 좌표·배열 순서,33개 결과 필드와 metadata를 검사한다. raw 유리수 필드는 같은 양 끝점이 필요하며, 폭이 뒤집힌/참값을 포함하지 않는 구간은 거부한다. 모든 구간 폭은 `(1+max(abs(endpoint)))*2^-256` 이하로 제한한다. 양의 판별 이득은 resolved positive sign을 유지해야 한다.

이 한도는 외부32자리 입력과512bit 생산 root의 조건수를 고려한 검증 허용 폭이다. **생산 알고리즘과 byte가 같은지**를 증명하는 기준은 아니다. 수학적으로 옳고 충분히 좁은 대체 구간은 허용한다. 표시값·부호·log·resolution은 보고 구간에서 공용 formatter로 재생성해 일치시킨다. 이 표시 primitive 자체를 별도 구현으로 증명한 것으로 과장하지 않는다.

## 변조 검사

64개 좌표 각각에서 구간을 옮기고 표시 metadata까지 다시 맞춘 거짓 응답을 거부한다. 표시값만 바꾼64개 경우도 거부한다. 표시 반올림으로 차이가 보이지 않는10^-100 구간 이동, 복소 비대각 전치, 고유값/효과/확률 좌표 교환, 전략·비유일성·입력·관례·정밀도 분류 변경을 검사한다.

정상적인 좁은 대체 구간은 받아들이고 참값을 포함하더라도 너무 넓은 구간은 거부한다. 검증 성공 후 원래 응답을 변경해도 소유한 결과는 변하지 않는다.

## 엔트로피·압축 추가 구현

[두 번째 독립 검증기](quantum-information-entropy-response-status.md)는 볼록 결합 행렬·Bell 고유공간·부분추적/전치와 별도 signed log1p 급수로 결합 정보량을 검사한다. 생산 atanh/log evaluator를 호출하지 않으며608항과 기하급수 꼬리 상계로512bit 로그 구간을 만든다. 유한 블록은 Pascal 덧셈·반복 곱·사전확률 순서와 누적 rank 구간으로 검증한다. 모든 수치 좌표와 표시 metadata를 확인한다.

엔트로피의 허용 폭은 `(1+max(abs(endpoint)))*2^-224`다. 정확 유리수 필드는 점 구간이어야 하며 엔트로피 필드는 독립 증명서 구간을 포함해야 한다. 작은 실제 값이 생산 정밀도에서 미해결인 것과 실제0을 구분한다. 공유하는 사칙연산/표시 primitive를 독립적인 엔트로피 evaluator로 오해하지 않는다.

## 앙상블 추가 구현과 관측 연동

[앙상블 검증기](quantum-information-ensemble-response-status.md)는 행렬 혼합·특성방정식·별도768bit 이분 root와512bit 로그로 확률표·엔트로피·선택 정보/상계를 검사한다. 유리수 root는 정확히 인식한다.23개 수치 좌표와 측정 규약을 확인하며, 정보량 최적화와 최소 오류 측정을 혼동하지 않는다.

원래/자른 구간을 보존하려면 개별 참값 포함 검사만으로는 부족하다. raw Holevo/측정 정보는 보고된 엔트로피 구간의 정확한 차이이고, 자른 결과는 그 raw 구간의 명시된 교차 연산이어야 한다. 조건부 행의 보완 관계와 결합 확률의 가중치도 연동한다. 기존 엔트로피 검증에도 raw/자른 탈위상 증가의 연동 검사를 보강했다. 대체 구간을 쓰면 파생 구간도 일관되게 갱신해야 한다.

## 상대 엔트로피 추가 구현

[네 번째 검증기](quantum-information-relative-response-status.md)는 정확 행렬 support·특성방정식·고유공간 trace·별도 root/log로 유한/무한 분류와 두 상태의 동일 Z 탈위상 전후를 확인한다. 일반 응답12수치 좌표와 모든 분기 필드를 검사하고, 스펙트럼/weight 보완 관계와 raw/최종값의 하한 자르기를 연결한다. 아주 큰 유한값을 무한대로, 작은 양의 값을0으로 바꾸지 않는다. 생산 내부에만 있는 입력 엔트로피 구간까지 관측했다고 주장하지 않는다. 실제 Worker는 아직 없다.

## 복제 불가·BB84 추가 구현

[다섯 번째 검증기](quantum-information-bb84-response-status.md)는 별도 정확 field·직접 CNOT 출력/tensor 좌표·진폭 겹침과 BB84 조건부 bit 채널로168계수·91관측값을 대조한다. Eve의 공개 관측 사후분포와 반복 곱 표본 확률을 확인하며 생산 회로/채널/프로토콜 모델을 호출하지 않는다.

최대 입력의 표본 확률은8천 자를 넘는 정확 계수를 만들 수 있다. 공용 복사기/endpoint의 기본 예산은 유지하되 BB84만 명시적으로 문자열16384자·계수10000자리·이진 지수32768을 사용한다. 선택 예산 자체도 상한을 검사한다. 이 확장은 입력 크기를 늘리는 것이 아니라 이미 허용된 입력의 정상 응답을 수용하기 위한 것이다.

## 텔레포테이션·초밀집 부호화 추가 구현

[여섯 번째 검증기](quantum-information-teleportation-response-status.md)는 세 site와 Bell 상태의 닫힌 전개식으로 모든 prefix·네 기록·보정 순서·확률·밀도행렬·전역 위상·통신 전 상태·자원을 대조한다. 메시지/순서에 따라602/618/634개의 정확 계수를 검사한다. 생산 회로를 재실행하지 않으며, Pauli 순서가 바뀌었을 때 밀도행렬이 같아도 raw 위상은 원래 요청과 일치해야 한다. 입력 기저 열로 만든 네 Kraus 연산자와 모든 행렬 단위의 보존도 검사한다.

## 오류 정정·Knill–Laflamme 추가 구현

[일곱 번째 검증기](quantum-information-error-correction-response-status.md)는 Pauli의 bit/위상 image와 코드 기저 내적으로 선택 오류·syndrome·복구·압축 교차 항을 구한다. IID X 채널은 별도 다수결/두 Bell projector 식으로 확인한다. 기본 네 오류 가족에서는1176정확 계수·10유리수 관측을 검사하며 가족 크기에 따라 계수 수가 달라진다. 퇴화 오류·복소 scalar·첫 반례·불가능한 가지와 최대16연산자를 확인한다. KL의 복구 존재 판정과 현재 X 복구의 성능, 입력별 fidelity와 얽힘 fidelity를 구분한다.

## 주요화·Bell 희석 추가 구현

[여덟 번째 검증기](quantum-information-majorization-response-status.md)는 쌍별 안정 순위·hinge 함수 비교로 주요화를 구하고, suffix에서 보고할 prefix를 만든다. 꼬리 제약의 정확 교차 곱/포화와 별도512bit 엔트로피로 최적 확률과 정보를 검증한다. 영 target 꼬리의 null과 작은 위반을 구분한다. 별도 Bell 희석은 직접 진폭 곱·완비성·두 보정 가지를 확인한다. 일반3차원46관측/16차원 full-rank228관측과 희석324계수를 검사한다. 보수적 엔트로피 구간이 참된 최대값을 감싸는 것은 허용하며, entropy로 부분 순서를 판정하지 않는다.

## 채널 용량 추가 구현

[아홉 번째 검증기](quantum-information-capacity-response-status.md)는 입력/출력 matrix-unit 작용·환경 행렬식·독립 root/log와 정규화 Choi로77관측을 확인한다. 선택 입력의 정보량과 가족 정리의 C/CE/Q를 분리한다. 순수/완전 탈위상에서의 구조적 영값과 raw 차이를 구분하고, 보고된 엔트로피/원래·자른 정보 구간의 연동도 확인한다. 알려진 탈위상 가족의 정리를 확인하는 것이며 범용 용량 최적화/유한 블록 부호기를 구현하지 않는다.

## 실제 Worker 연결과 다음 게이트

아홉 검증기의 수학·metadata·요청 binding·변조 거부와 통합 진입점을 준비했다. 별도 계산/독립 검증 Worker와 controller/hook을 추가하고 실제 module Worker에서 순번·취소·입력 교체·오류/재시도·deadline·종료를 확인했다. 근거는 [Worker 상태](quantum-information-worker-status.md)다. 이 native harness 결과를 production reader 완료로 기록하지 않는다. 다음은 교수 화면과 실제 reader 등록/생산 자산 검증이다.
