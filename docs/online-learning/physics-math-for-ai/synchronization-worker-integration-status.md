# 동기화 세 가족: 입력 계약과 Worker 계산 연결

2026-11-08. [세 수치 모형·한영 원고](synchronization-three-families-foundation-status.md) 다음 단계로 화면용 입력 계약, 공통 Worker 전송·응답 검증 및 계산 수명주기를 구현했다. **교수 화면·읽기 등록은 아직 미완료**다. 기존545단원·1635안내, 원래298/362입문 검증·64미완료와 전체51영역509주제·연구 깊이·공용 그림 후속 범위를 유지한다.

## 화면과 계산의 경계

Hopf와 두 위상 진동자의 입력 인터페이스·검증기를 별도 `*-input.ts`로 분리했다. 기존 수치 모듈은 같은 인터페이스를 다시 내보내므로 기존 검사·호출 경로를 유지한다. 유한 Kuramoto의 기존 입력 모듈도 공통 전송에 연결했다. 정확한 유리수 입력의 부호·동일성을 보존하고, 집단의 두 배열을 복사·동결한다. 객체 필드 순서가 달라도 같은 준비의 키는 같다.

`learning-synchronization-protocol.ts`는 세 가족의 식별자·입력·요청 번호·정규화된 입력 키를 검증한다. 결과 전체 필드, 수치 관측 구간, 행렬·배열 길이, 기록 순서·시각·끝점 일치와 분류를 확인한다. 예를 들어 양의 μ의 평형 원/주기 궤도, 잠김 판별식과 고정 위상, 유한 집단의 비교 임계 가지를 입력과 대조한다. 반올림 표시에서 같은 숫자로 보이는 임계 양쪽도 정확한 유리수 부호로 구별한다.

이 검사는 전송 구조와 명시한 입력의 일치 검사다. 신뢰할 수 없는 송신자가 만든 모든 유한 숫자의 수학적 진실성을 증명하지는 않는다. 계산의 정확도는 앞 단계의 독립 수치·해석 참조 검사로 별도 확인한다. 유한 RK4 오차 추정을 엄밀한 경계로 바꾸지 않는다.

화면 컨트롤러와 프로토콜을 브라우저용으로 묶어 의존성 그래프를 확인했다. 수치 모형·행렬 지수·고정밀 지수/로그 계산 엔진은 메인 화면의 이 묶음에 포함되지 않는다. Worker 전용 평가기가 세 모형을 호출한다. 이 단계의 브라우저 검사는 esbuild로 묶은 실제 Worker 진입 파일을 사용하며, 아직 Next 빌드 자산이나 최종 읽기 화면을 검증한 것은 아니다.

## 계산 수명주기와 저장 입력

요청마다 Worker를 하나 생성한다. 새 요청은 진행 중인 계산을 종료하므로 긴 동기 계산 뒤에 대기하지 않는다. 계산 시작 알림 뒤에 입력과 맞는 결과만 공개한다. 취소·완료·오류·화면 해제에서 Worker를 종료하고 이벤트 처리기를 해제한다. 오래된 요청 번호와 이미 종료한 Worker의 콜백은 현재 결과를 바꾸지 못한다. 실패 때 메인 화면에서 동기 계산으로 대신하지 않는다.

`use-synchronization-calculation.ts`는 렌더 입력의 키와 응답 키가 같을 때만 결과를 노출한다. effect가 새 요청을 설치하기 전 렌더에서도 이전 입력의 결과가 잠깐 표시되지 않도록 했다. 재시도와 취소 함수도 제공한다. 실제 React 읽기 화면에서의 연결·검증은 다음 단계다.

초안·저장 JSON 파서는 원래 숫자 토큰을 검사한다. 소수 반올림으로 정수가 된 입력, 0으로 언더플로한 비영 값, 범위 밖 정수와 잘못된 저장 버전을 거부한다. 유한 집단 배열의 숫자에도 같은 정수 검사를 적용한다. 파서만 준비했으며 실제 저장·복원 UI의 브라우저 완료를 주장하지 않는다.

## 실제 확인한 범위

| 확인 대상 | 근거 |
| --- | --- |
| 모형·원고 회귀 | 이전152검사 통과 |
| 전송·수명주기·분기 메타데이터 | 새119검사, 세 가족 독립 준비111개 포함 |
| 실제 Chromium Worker | 111입력의 시작·결과 전송과 응답 검증 |
| 시작 직후 종료 | 각 가족1회, 총3회 |
| 실제 컨트롤러 수명주기 | Worker8개 생성·8개 종료·잔존0, 취소3회·교체·의도한 Worker 오류 후 재시도·해제 |
| 타입·lint | 통과 |

잘못된 응답·비정상 숫자·추가 필드·다른 준비·잘못된 분기·기록 순서·구간 분모 오류도 거부하는지 검사했다. 생성 불가·전송 실패·messageerror·오류 메시지·취소·재진입 콜백을 점검했다. 브라우저 자체 오류는0건이다. 기존 등록 콘텐츠·참조·원고·정적 출력은 보존했다. 공개 배포·commit·push는 수행하지 않았다.

재현: `npx tsx --test scripts/learning-synchronization-worker.test.ts`, `npx tsx scripts/check-synchronization-worker.ts`. 후자는 기존 로컬 미리보기 `localhost:4175`에서 별도 검증 자산을 제공한다. 상세 결과는 `.runtime/learning/synchronization-worker/verification.json`과 `native-worker.json`이다.

## 다음 구현

세 가족의 고정 개념 그림 → 조작과 상태 비교 → 물리 시간에 따른 재생과 정지 → 안내 실험·퀴즈·저장 복원 → 한영 실제 읽기를 연결한다. 기존 홈페이지의 색·서체를 유지하며 진입은 **도서 → Interactive Book**이다. Online Book 목록에 교재 링크를 넣지 않는다. 키보드·터치·명암·모바일·접근성과 Next 정적 출력까지 검증한 뒤에만 새 단원을 등록하고 원래 주제의 입문 완료 수를 갱신한다. 그 후 coarse graining과 남은 영역을 순서대로 이어간다.
